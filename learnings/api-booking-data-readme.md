# API Booking Data Builder - Detailed Explanation

## Overview

This document explains the booking data builder code, line by line, including all questions and answers discussed.

```ts
import { faker } from '@faker-js/faker';
import type { Booking } from '../api/BookingApi';

function isoDate(daysFromNow: number): string {
  const d = faker.date.soon({
    days: daysFromNow,
    refDate: '2026-01-01T00:00:00'
  });

  return d.toISOString().slice(0, 10);
}

export function buildBooking(
  overrides: Partial<Booking> = {}
): Booking {
  return {
    firstname: faker.person.firstName(),
    lastname: faker.person.lastName(),
    totalprice: faker.number.int({ min: 100, max: 1000 }),
    depositpaid: faker.datatype.boolean(),
    bookingdates: {
      checkin: '2026-02-01',
      checkout: isoDate(30),
    },
    additionalneeds: faker.helpers.arrayElement([
      'Breakfast',
      'Late checkout'
    ]),
    ...overrides,
  };
}
```

# What this code does

This is a test-data builder commonly used in API automation frameworks. It generates realistic booking data using Faker so tests do not need to manually create booking payloads from scratch.

## Helper Function

```ts
function isoDate(daysFromNow: number): string
```

Creates a utility function that returns a date formatted as:

```txt
YYYY-MM-DD
```

### Generate a future date

```ts
const d = faker.date.soon({
  days: daysFromNow,
  refDate: '2026-01-01T00:00:00'
});
```

`faker.date.soon()` generates a future Date.

- `days` specifies the maximum number of days in the future.
- `refDate` specifies the starting point.

Example:

```ts
isoDate(30)
```

means:

> Generate a random date within 30 days after January 1st, 2026.

### Understanding refDate

```ts
'2026-01-01T00:00:00'
```

Breakdown:

```txt
2026-01-01  -> Date
T           -> Date-Time separator
00:00:00    -> Midnight (hours:minutes:seconds)
```

Meaning:

```txt
January 1, 2026 at 12:00:00 AM
```

The time portion makes the date explicit and avoids parsing ambiguity.

### Convert to ISO Date String

```ts
d.toISOString().slice(0, 10)
```

Example:

```txt
2026-01-18T14:25:31.000Z
```

becomes:

```txt
2026-01-18
```

# Potential Issue Found

The code may generate invalid booking data.

Example:

```json
{
  "checkin": "2026-02-01",
  "checkout": "2026-01-15"
}
```

In this case:

```txt
checkout < checkin
```

which is logically incorrect.

A better implementation would generate checkout relative to checkin so checkout is always later.

# additionalneeds Explained

```ts
additionalneeds: faker.helpers.arrayElement([
  'Breakfast',
  'Late checkout'
])
```

## What does arrayElement do?

It randomly selects ONE item from an array.

Input:

```ts
['Breakfast', 'Late checkout']
```

Possible result:

```txt
Breakfast
```

or

```txt
Late checkout
```

## Why use it?

To add realistic variation to test data.

Without Faker:

```ts
additionalneeds: 'Breakfast'
```

Every booking would contain the same value.

With `arrayElement()`:

Different test runs may generate different booking requests.

## Why is it a string instead of an array?

Because:

```ts
arrayElement()
```

returns a single value.

Example:

```txt
Breakfast
```

Not:

```json
["Breakfast", "Late checkout"]
```

That would require:

```ts
arrayElements()
```

# Why use ...overrides?

```ts
...overrides
```

Uses the JavaScript spread operator.

It copies user-provided properties into the returned booking object.

Example:

```ts
buildBooking({
  firstname: 'Pramod'
})
```

Result:

```json
{
  "firstname": "Pramod"
}
```

The generated first name is replaced.

## Why place it last?

Because later properties override earlier properties.

Example:

```ts
{
  firstname: 'John',
  ...{ firstname: 'Pramod' }
}
```

Result:

```ts
{ firstname: 'Pramod' }
```

If `...overrides` appeared first, Faker-generated values would overwrite custom test values.

# FAQ

## What does T00:00:00 mean?

It means midnight.

```txt
2026-01-01T00:00:00
```

represents January 1st, 2026 at 12:00 AM.

## Why use refDate?

It tells Faker where to start calculating future dates.

## What is stored in d?

A JavaScript Date object.

## Is checkout potentially before checkin?

Yes. Based on the code shown, that can happen and is likely a bug or unfinished test data logic.

## Why use additionalneeds?

To simulate optional guest requests and improve test coverage.

## Why use overrides?

To allow tests to modify only the fields they care about while letting Faker generate everything else.
