How our tests get their secrets

The .env story, in small words.

1 A notebook nobody shares

One file, .env, sits in the project folder. It holds the boring-but-private stuff: which website to visit, which user to log in as.

🗒️.envreal values — hidden
↔
📋.env.examplesame key names, fake values — shared
Rule. .env is in .gitignore. The example file is the map; the real file is the treasure. Never commit the treasure.

2 Somebody reads it out loud — once

At the very top of the config, one line reads the notebook and pours every key into the computer's memory. That happens before any test starts, so every test already knows everything.

// playwright.config.ts (line 4)
import dotenv from 'dotenv'
dotenv.config();
🗒️.env
→
📣dotenv.config()runs once, in the config
→
🧠process.enveveryone can read
→
🧪tests
Do not call dotenv.config() again inside a spec. dotenv never overwrites a key that already exists, so the second shout does nothing.

3 Little helpers do the reading

Tests don't poke at process.env themselves. Four tiny functions in src/config/env.ts do it politely.

  • 🎁
    env('KEY', 'backup')
    Value, or the backup when it's missing.
  • 🚨
    requireEnv('API_TOKEN')
    No value? Throw right away, with a helpful message.
  • 🔘
    envFlag('ATTACH_SCREENSHOTS')
    true/1/yes means on. Anything else, off.
  • 🔢
    envNumber('KEY', 5)
    A number, or the backup if it's gibberish.
import { env } from '@config/env';
const FIRST_ITEM_ID = env('TTA_ITEM_ID', 'test-allthethings-tshirt-red');

4 Empty means "not there"

If a line says STANDARD_USER= with nothing after it, that counts as missing — so the backup is used. An empty username would be worse than none.

✗ plain ??

Only catches undefined. A blank line sneaks through and tests log in as "".

✓ env()

Trims, then treats blank as missing. Backup kicks in.
Why it matters. The npm scripts run cross-env BASE_URL= TTA_ENV=stg …. That blank BASE_URL= is the whole trick — it has to read as "unset" so TTA_ENV can win.

5 Picking the website: a ladder

Three rungs. The first one with something on it wins.

  • 1️⃣
    BASE_URL
    Set? Done. Nothing else is even looked at.
  • 2️⃣
    TTA_ENV → QA_ / DEV_ / STG_ / PROD_ / API_BASE_URL
    Defaults to qa. Aliases: local, staging, production…
  • 3️⃣
    hard-coded default
    Baked into the switch per environment.
Trap. A BASE_URL= line with a real value in .env pins every run to one host and makes TTA_ENV useless. That's why the test:qa/test:stg scripts blank it first.

6 The word we're not allowed to use

Windows already gives every program a USERNAME. dotenv won't overwrite it. So USERNAME=admin in .env is thrown away — quietly. No error. No warning. Tests just log in as the wrong person.

🪟 🚫 🗒️

✗ USERNAME / PASSWORD

Shadowed by the OS, or read by nothing.

✓ STANDARD_USER / TTA_SECRET

Project-prefixed. Can't collide. Already read by credentials.ts.
How it was caught. The file had 13 keys, the runner said injected env (12). Exactly one was swallowed.

7 Proving it actually works

A green test proves nothing — a test that ignores .env and uses its backup also goes green. So: break it on purpose.

$env:TTA_ITEM_ID="false-id"; npx playwright test src/tests/e2e/e2e-checkout-env.spec.ts

waiting for locator('[data-test="add-to-cart-false-id"]')
1 failed   ← good. The value is really being used.
And leave a note. One log line per test prints what resolved:
Env: user=standard_user item=test-allthethings-tshirt-red baseURL=https://app.thetestingacademy.com
